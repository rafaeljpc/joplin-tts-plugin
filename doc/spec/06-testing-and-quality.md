# 06 — Testing and quality

## Joplin best practices adopted

- Structure generated by `generator-joplin` (`src/`, `api/`, `webpack.config.js`, `plugin.config.json`, `publish/`).
- npm package named `joplin-plugin-*` with the `joplin-plugin` keyword and `files: ["publish"]`.
- Complete `manifest.json`: unique reverse-notation `id`, `app_min_version`, `categories`, `repository_url`, `homepage_url`.
- Settings registered in their own section, with prefixed keys and secrets marked `secure: true`.
- Commands registered through `joplin.commands` and exposed via toolbar/menu (no stray shortcuts).
- English interface with a pt-BR translation; no runtime dependencies (small bundle).
- Version kept in sync between `package.json` and `manifest.json` (`npm run updateVersion`).

## Testing strategy

Jest + ts-jest. The code is organized so that almost everything is pure and testable:

| Layer                    | How it is tested                                                            |
| ------------------------ | --------------------------------------------------------------------------- |
| `lib/*` (logic)          | Pure unit tests; engines with `speechSynthesis`/`fetch`/`Audio` _fakes_     |
| `webview/player.ts` (UI) | `jest-environment-jsdom`: simulated real DOM, simulated messages, clicks    |
| `plugin.ts` / `index.ts` | Joplin API replaced by a _mock_ (`test/mocks/joplinApi.ts`)                 |
| `.github/scripts/*`      | Unit tests for the coverage-badge generator (`test/coverageBadges.test.ts`) |

- **Required minimum coverage** (fails CI): 100% statements, lines and functions; 95% branches. The project is currently at 100% on every metric.
- Covered scenarios include: cancellation during a request, stale utterances after pause/seek, `Intl.Segmenter` fallback, late-loading voices, API errors, wrapped-format messages, hidden panel, note switching.

## Local verification

```bash
npm run validate   # eslint + prettier --check + tsc --noEmit + jest --coverage
npm run dist       # produces publish/com.rafaeljpc.joplin-tts.jpl
```

## Limits of automated tests

The _fakes_ guarantee the logic, **not** the real behavior of `speechSynthesis` in Electron, the Android WebView or iOS. Those points require manual testing on each platform (see the checklist in [07-roadmap-and-decisions.md](07-roadmap-and-decisions.md)).
