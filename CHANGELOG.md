# Changelog

All notable changes to this project are documented here. Format based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- On Joplin mobile the player is shown in a plugin dialog sized to its content (`setFitToContent`, no button row) instead of the full-screen panel, so it is only as tall as the player. A dialog is modal: the note stays visible but dimmed and untouchable, and the dialog closes with a tap outside it or the back button (which also stops the reading). Reading starts from a tap on Play inside the dialog, which owns the audio element. The panel cannot be docked at the bottom of the screen on mobile (Joplin gives plugins no way to position it), which is why a dialog is used. The advanced setting _Player in a dialog_ (mobile) switches back to the panel after restarting Joplin. Desktop is unchanged.
- Joplin mobile: the player now has a touch layout (untested on a device) closer to the prototype: content pushed to the bottom of the panel with a drag-handle, the current sentence in a card labelled "Sentence N of M", a large round play/pause button, speed chips (1×, 1.25×, 1.5×, 2×) and a voice selector. Joplin owns the panel modal on mobile and does not let plugins resize or dock it, so it is not a true bottom sheet. Desktop is unchanged.
- Joplin mobile compatibility (untested on a device): the manifest declares `platforms: ["desktop", "mobile"]`, so Joplin for Android no longer lists the plugin as incompatible. On mobile the plugin does not load Node modules, Piper (its engine, voice dialog, command, menu item and the _Piper voices URL_ setting) is not offered, and a synced Piper choice falls back to the system voices.

### Fixed

- Online engines (Google Translate, Google Cloud, Azure, Piper) on Android: every sentence asked for a new tap ("play() can only be initiated by a user gesture"). Playback now reuses one audio element that the first tap unlocks, so later sentences play on their own. If a read-aloud starts without a tap (autoplay from the plugin), the panel asks to "Tap Play to start" (translated). Desktop is unchanged.
- The plugin no longer stops loading when a view the platform lacks fails (editor and viewer scripts, toolbar buttons, Tools menu, Piper setup): each is optional and logs a warning instead.
- System voices on Android: speech that is accepted but never starts now fails after 5 seconds with a clear message instead of hanging silently, an empty system voice list explains that the WebView has no speech engine, and both suggest the online Google Translate engine (the text is then sent to Google). The utterance is also kept referenced and a paused synthesizer is resumed before speaking.

### Added

- README: platform support matrix (Windows, macOS, Linux, Android, iOS) per speech engine, with what has been tested.

## [0.4.0] - 2026-11-11

### Added

- **Piper**, an offline neural speech engine. Voices are downloaded by the user (none by default, with the size of each shown) from a catalog whose URL is the new advanced setting _Piper voices URL_, and stored in the plugin's data folder. Choosing the engine opens a voice dialog that cannot be left without a downloaded voice (or going back to another engine); **Tools → Joplin Text-to-Speech: Piper voices** reopens it. The internet is needed only for the downloads.

### Fixed

- Piper: the ONNX Runtime script is now evaluated by a small loader (it cannot read files in the plugin process), and phonemes are numbered with the voice's own `phoneme_id_map`; both were found by the new integration test, which downloads a pt-BR voice and speaks.

- Piper no longer fails with "Cannot read properties of undefined (reading 'wasm')": the ONNX Runtime script it downloads is now the CommonJS build, and a runtime that does not load is reported with a clear message.

### Changed

- Dependency injection is centralized: a composition root per runtime (`src/compose`, and the panel's engine registry), explicit dependencies for Piper and the Piper-without-a-voice rules in their own class. No behaviour change.

## [0.3.1] - 2026-11-10

### Changed

- Coverage badges are regenerated by `npm run validate` and committed with the code; CI only checks they are current, so no workflow pushes to `main` anymore.

## [0.3.0] - 2026-11-10

### Added

- The sentence being read is highlighted inside the note: in the Markdown editor (CodeMirror 6, with scrolling) and in the rendered viewer.

### Changed

- `npm run version:set -- X.Y.Z[-dev]` sets the version in `package.json`, `package-lock.json` and the manifest at once; development of a version starts at `X.Y.Z-dev` so local packages are identifiable, and the release workflow refuses to publish a `-dev` version.
- Release automation: merging a new version into `main` creates the tag and publishes the GitHub release with the `.jpl`; the notes come from this changelog.

## [0.2.0] - 2026-11-10

### Added

- Online engines (Google Translate, Azure, Google Cloud) fetch the next sentence's audio while the current one plays, removing the pause between sentences.

## [0.1.2] - 2026-11-10

### Added

- Reading speeds 2.5× and 3× in the player.

## [0.1.1] - 2026-11-10

### Changed

- Reorganized `src` into `domain`, `application`, `adapters` and `webview` layers; the dependency rule is enforced by ESLint. No behaviour change.
- Split the panel's `initPlayer` into a view, a settings manager and a message handler. No behaviour change.

## [0.1.0] - 2026-11-10

### Added

- In the Markdown editor, reading starts at the sentence under the cursor; the player's play button honours it.
- If text is selected in the editor or the rendered viewer, only that selection is read.
- Player panel with voice picker, play/pause, previous/next/stop, speed and progress.
- Toolbar button, Tools menu item and `Ctrl/Cmd+Alt+R` shortcut.
- Speech engines: system voices (Web Speech), Google Translate, Microsoft Azure Speech and Google Cloud Text-to-Speech.
- Button in both the note toolbar and the editor toolbar.
- Markdown-to-speech conversion and sentence splitting.
- English and Portuguese (pt-BR) interface.
- Design documentation in `doc/spec`.
